# 地点标注工作台 iPad 离线版

这是 `NEWPROHECT` 的独立静态版本。GitHub Pages 只发布程序文件；导入的文章与标注保存在当前 iPad 的浏览器存储中，不会自动上传到 GitHub。

## 发布到 GitHub Pages

1. 新建一个专门发布此版本的 GitHub 仓库。把**本文件夹里的内容**上传到仓库根目录，包括 `index.html`、`sw.js`、`storage.js`、`manifest.webmanifest`、`.nojekyll` 等。不要上传 `NEWPROHECT/data`、`NEWPROHECT/JSON` 或自己的标注数据。
2. 在仓库 **Settings → Pages** 中选择 **Deploy from a branch**，分支选 `main`、目录选 `/ (root)`，保存。
3. 等 Pages 地址可访问后，在 iPad Safari 打开该 HTTPS 地址，从分享菜单选择“添加到主屏幕”。以后从主屏幕图标进入同一个工作台。

若想继续使用现有大仓库发布，需要另外配置 GitHub Actions；Pages 的普通分支发布不能直接选本文件夹作为来源。

## 课堂使用

1. 在线打开主屏幕工作台，等顶部显示“**离线已就绪**”。
2. 导入城市 JSON；以后打开会恢复当前工作区。蓝牙鼠标可用于正文拖选和调整标注范围。
3. 上课前打开飞行模式，重开主屏幕工作台，确认文章与标注仍在，并试一次备份下载。
4. 课堂中定期点 **完整备份**，在 iPad“文件”App 中确认下载的 JSON 确实存在。完整备份含所有文章、跳过状态、审核状态和当前文档；可用“导入 JSON”恢复。
5. **导出修改文件**沿用原工作台的数组格式，排除“不标记此篇”的整篇文章，适合交给电脑端后续流程。它不包含单独保存的“审核完”状态，因此不能代替完整备份。

导入新文件会替换本机当前工作区，应用会先提示确认。不同浏览器、Safari 标签页和主屏幕应用可能使用不同的存储空间；建议一直从主屏幕图标进入。浏览器存储仍可能被系统清理，完整备份应保存在“文件”App 或其他设备上。

## 更新程序

修改网页文件后，把 `sw.js` 中的 `CACHE` 版本号加一再上传。iPad 联网打开应用，让新版缓存完成，然后关闭并重开。发布程序时不要把文章 JSON 放进仓库。

## 本地检查

在本目录运行 `python -m http.server 8766`，电脑浏览器打开 `http://localhost:8766`。正式的离线功能请用 GitHub Pages HTTPS 地址检查；普通局域网 HTTP 地址不能用于安装 Service Worker。
